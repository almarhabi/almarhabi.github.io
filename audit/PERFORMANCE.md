## الطريقة

- Chromium فعلي `154.0.8037.57`، headless، viewport390×844 مع mobile/touch، وdeviceScaleFactor1، وCDP CPU throttling4×.
- عشر browser contexts جديدة لكل نسخة، مع تعاقب baseline→snapshot ثم snapshot→baseline لتقليل انحياز الترتيب. عملية المتصفح نفسها كانت شغّالة؛ «تحميل جديد» يعني context/cache جديدين، وليس إطلاق browser process جديدة.
- الخادم loopback واحد مع `no-store`. طلبات الخطوط والموارد الخارجية استُبدلت محليًا بموارد فارغة؛ وأزيلت preconnect hints من النسخ المقدمة للاختبار فقط. لم يتغير inline JavaScript أو CSS الفعلي للنسختين في هذه الخطوة.
- بيانات تطبيق جديدة مع جدول المحاضرات المضمّن وتفضيلات متطابقة تطفئ الحركة والصوت والاهتزاز. لا تاريخ مستخدم حقيقي ولا تسجيلات ولا إعداد Firebase أو AI أو credentials. لذلك لا يقيس الاختبار حسابًا ضخمًا.
- قياس العمليات الدافئة بـ`performance.now` مع قراءة layout إجبارية. الرسم الكامل يزيد `LV` لإبطال derived caches كما بعد تغيير البيانات. الفتح ينفذ `go(id)` الحقيقي، والحفظ `savePatch(id,{bm:...})` الحقيقي ويشمل localStorage والرسم.
- حفظ bookmark محلي فقط؛ لا يشمل انتظار إقرار Firebase أو معالجة ANKI أو AI.
- احتُفظ بكل العينات، بما فيها أول عينة والoutliers. أوقفت عمليات الاختبارات والتثبيت الأخرى أثناء هذه الجولة لتقليل تنافس CPU. هذه جولة كاملة للمصدر الأحدث بعد إيقاف الاختبارات والمتصفحات الأخرى؛ لم تُخلط بعينات الجولات الأقدم ولم تُحذف outliers من الجولة المنشورة. يظل المضيف مشتركًا وتباينه محتملًا.
