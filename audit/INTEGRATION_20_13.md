# فحص ترابط الخدمات — 20.13

## النتيجة

أُصلحت أخطاء مثبتة عند حدود GitHub والتخزين والمزامنة، وأضيف اختبار متصفح يصل التوليد ببناء Python الحقيقي وتنزيل النتيجة من جهاز آخر. طُبّق كذلك تفضيل 10–13 صفحة لكل جزء مع حد أدنى 7، مع بقاء الأهداف والفواصل والعُقد خارج سقف البطاقات الأساسي.

هذا لا يثبت خلو الموقع من الأخطاء، ولا يثبت أن إعدادات الحسابات الخارجية تعمل. **التحقق الحي الكامل للخلفية متوقف على إعداد `UQU_RUNNER`.**

## الأخطاء المثبتة والإصلاح

| المشكلة | الأثر | الإصلاح والتحقق |
|---|---|---|
| لا توجد مهلة لقراءة رد GitHub | انتظار بلا نهاية عند توقف جسم الرد | النقل المشترك يحد الطلب والجسم بـ45 ثانية؛ اختبار جسم متوقف |
| الإلغاء أثناء قراءة JSON يخرج كخطأ عادي | رسالة شبكة بدل إلغاء المستخدم | حفظ حالة `abort` عبر API والتنزيل العام؛ اختبارات الإلغاء أثناء القراءة |
| رد HTML بحالة HTTP200 يخرج كـSyntaxError | فشل مبهم | خطأ خدمة واضح للرد غير الصالح |
| تنزيلات GitHub بلا حد للحجم | استهلاك ذاكرة واتصال زائد | 4MB لردود JSON و50MB لملف APKG، وإيقاف النقل عند رفض الحجم |
| حذف يصل أثناء قراءة IndexedDB | إعادة ملف محذوف من الذاكرة | فحص الصلاحية قبل وبعد الانتظار؛ اختبار حذف متزامن |
| طلب ملغى يرجع ملفًا مخزّنًا | استمرار تنزيل بعد الإلغاء | فحص الإلغاء قبل قراءة الذاكرة |
| وصول مجموعة أحدث أثناء التحميل | عرض نسخة أقدم | التحقق من هوية المجموعة وتوقيت الحذف والمسح عبر مسار التحميل والعرض |
| تجاهل رفض حفظ مراجعة قديمة | إظهار بيانات ألغاها جهاز آخر | تمرير خطأ الحفظ وفحص المرجع بعده |
| الخلفية تعلن20.10 والواجهة20.12 | تشخيص إصدار مضلل | توحيد20.13 واختبار تطابق الإصدار |
| الخلفية غير معدّة لكنها تظهر نجاحًا | الانطباع بأن العمل أُنجز | فحص إعداد منفصل، تحذير وملخص، وتخطي خطوات التشغيل عند غيابه |

أُضيفت عشرة اختبارات حدود إلى `integration-regressions.cjs`، وفشلت كلها على النسخة السابقة ثم نجحت بعد الإصلاح. الاختبارات الأخرى تبقى لمنع تراجع وظائف موجودة.

## ما اختُبر

- 29 مجموعة فحوص محلية نجحت أثناء المراجعة: المنطق، الإلغاء، التخزين، المزامنة، الوكيل، Apps Script، مشغّل الخلفية، Python، الواجهة، الصوت، الإتاحة ومكتبات CDN المثبتة. بعد التعديلات الأخيرة أعيدت فحوص الأجزاء المتأثرة؛ ويعيد CI الفحوص على المصدر المنشور.
- 40 اختبار Python، بما فيها الاستيراد وإعادة الاستيراد ببرنامج Anki الفعلي.
- 16 اختبار عقود بين الخدمات، و15 اختبار حدود الردود والتنزيلات.
- 21 اختبار للأهداف والتقسيم، منها جميع أحجام المحاضرات من1 إلى500 صفحة وأمثلة10–13 صفحة.
- 10 اختبارات متصفح للمحاضرة والبطاقات والحذف. المسار الجديد يستخدم `aiCall` الحقيقي مع ردود نموذج وهمية، و`ghReq` الحقيقي مع HTTP وهمي، ثم `job.py` و`build_apkg.py` الحقيقيين، ثم جهازًا مستقل التخزين بلا token ينزل APKG والمراجعة ويتحقق من الحذف.
- 27 تحققًا بمحاكي Firebase الرسمي:16 لقواعد الوصول،9 لمعاملات عميلين حقيقيين،2 لاتصال long-poll تحت CSP الفعلية.
- اختبار مشغّل الخلفية يشغّل Chromium الحقيقي مع Kimi وهمي. أضيف اختبار لتشغيل فحص الإعداد في bash على إعداد فارغ، ومسافات فقط، وإعداد حاضر، مع التأكد من عدم طباعة السر.

أوامر الفحص الأساسية:

```sh
node tools/audit/validate.cjs
node tools/audit/csp.cjs
node tools/audit/integration-regressions.cjs
node tools/audit/ai-boundaries.cjs
node tools/anki/test_objectives.js
node tools/anki/test_browser.js
node --test tools/runner/test_runner.mjs tools/runner/test_anki_save.mjs
python3 -m unittest discover -s tools/anki -p 'test_*.py'
python3 tools/audit/run-firebase.py
```
